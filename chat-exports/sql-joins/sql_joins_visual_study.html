SQL JOINs — Visual Study

A JOIN combines rows from two or more database tables based on a relationship between their columns.

Instead of storing everything in one large table, we store related information in separate tables and combine it whenever required.

12. JOINing three or more tables
SQL allows multiple JOIN operations in one query.
SELECT c.name,
       p.name AS product,
       p.price
FROM customers c
JOIN orders o
  ON c.id = o.customer_id
JOIN products p
  ON o.product_id = p.id;
Extended schema example: orders now contains a product_id instead of the product name.

14. Finding unmatched records — ANTI JOIN
Suppose you want to identify customers who have never purchased anything.
SELECT c.name
FROM customers c
LEFT JOIN orders o
  ON c.id = o.customer_id
WHERE o.order_id IS NULL;
Test a right-side column that cannot be NULL in an existing order.
Another common approach is NOT EXISTS, which directly checks that no matching row exists.
SELECT c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.id
);


15. JOIN with GROUP BY
JOINs are often used to create reports and analytics.
SELECT c.name,
       COUNT(o.order_id) AS total_orders
FROM customers c
LEFT JOIN orders o
  ON c.id = o.customer_id
GROUP BY c.id, c.name;
Alice1 orders
Bob2 orders
Charlie0 orders
David0 orders
COUNT(o.order_id) ignores NULL values, so customers without orders correctly receive a count of zero.
Using COUNT(*) instead would count the unmatched placeholder row and incorrectly report one order for Charlie and David.


16. How databases execute JOINs internally
The database query optimizer chooses a physical execution algorithm based on factors such as table sizes, indexes, memory and estimated row counts.
Nested loop JOIN
For each outer row, search for matching inner rows. Indexes can make the inner lookup efficient.
Hash JOIN
Build a hash table from one input, then probe it with keys from the other input. Common for equality joins.
Merge JOIN
Walk through ordered inputs, matching equal keys. Sorting may be required first.
In PostgreSQL, use EXPLAIN or EXPLAIN ANALYZE to inspect the execution plan. EXPLAIN ANALYZE actually executes the statement.
