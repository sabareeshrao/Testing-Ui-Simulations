GitHub Actions — CI/CD and DevOps

GitHub Actions
Build · Test · Automate · Deploy
Official documentation

GitHub Actions is an automation platform built into GitHub that allows developers to automatically build, test and deploy software whenever specific events occur in a repository.

Instead of manually executing commands every time you change your code, GitHub Actions executes your configured workflow.

A file or build output retained after execution.

5. Workflow architecture

Independent jobs can execute concurrently. Steps inside a job normally execute in order on the same runner.

18. GitHub Actions in your GitHub Pages workflow
Consider your interactive learning pages in the Testing-Ui-Simulations repository.
Testing-Ui-Simulations
Static HTML learning website
Your learning website
Open Testing-Ui-Simulations
Illustrative publishing lifecycle, not an audit of your repository's actual workflow configuration.
GitHub Pages can publish directly from a configured branch or through a custom Actions workflow.
Example custom Pages deployment
yaml
name: Deploy static website

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  deploy:
    runs-on: ubuntu-latest

    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - uses: actions/checkout@v4

      - uses: actions/configure-pages@v5

      - uses: actions/upload-pages-artifact@v3
        with:
          path: ./site

      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
This example assumes your publishable website is in a site/ folder and the Pages publishing source is set to GitHub Actions. It is not a workflow installed in your repository.

24. Interview answer
GitHub Actions is an integrated automation and CI/CD platform that enables developers to automate building, testing and deploying applications.
Workflows are defined using YAML files in the .github/workflows directory. They are triggered by events such as pushes, pull requests or scheduled executions.
Each workflow contains jobs that execute on runners. Jobs contain steps that either execute shell commands or invoke reusable actions.
GitHub Actions also supports job dependencies, matrix execution, caching, artifacts, secrets and deployment environments, making it useful for implementing automated software delivery pipelines.
