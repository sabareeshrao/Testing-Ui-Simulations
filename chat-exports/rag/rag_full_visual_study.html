RAG — Retrieval-Augmented Generation

Retrieval-Augmented Generation (RAG) is a technique that allows a Large Language Model (LLM) to retrieve relevant information from an external knowledge source before generating an answer.

Instead of depending entirely on what the model learned during training, RAG supplies it with additional information at the time of answering.

2. Why do we need RAG?

A traditional LLM has several limitations when answering questions about private, recent or specialized information.

Knowledge limitations
The model may not know information created after its training.
Hallucinations
It may generate plausible but incorrect information.
Private information
It may not know internal company policies or documents.
Missing sources
It may be unable to identify evidence supporting its answer.

RAG addresses these limitations by retrieving information from external knowledge sources. However, it does not completely eliminate hallucinations.

19. What happens when RAG fails?

Poor chunking
Relevant information is split across disconnected chunks.
Improve chunk boundaries and overlap.
Poor embeddings
Unrelated concepts receive misleadingly similar vectors.
Evaluate and improve the embedding model.
Retrieval failure
The required document does not appear in search results.
Improve retrieval, indexing or query rewriting.
Irrelevant context
Too many unrelated chunks are passed to the LLM.
Apply reranking, filtering and context selection.
Generation failure
The LLM misinterprets or invents information despite retrieved evidence.
Improve grounding instructions and verify claims.
Outdated knowledge
Retrieved documents contain obsolete information.
Refresh documents and remove outdated embeddings.

Security is equally important. A RAG system should enforce document permissions during retrieval, protect sensitive information and treat retrieved content as untrusted data rather than instructions.

21. Build a simple RAG application using Python

Here is a minimal implementation of RAG without using a large orchestration framework.

Install dependencies

bash
pip install chromadb sentence-transformers openai

Step 1 — Initialize the components

python
import os
import chromadb
from sentence_transformers import SentenceTransformer
from openai import OpenAI

embedding_model = SentenceTransformer(
    "all-MiniLM-L6-v2"
)

db = chromadb.Client()

collection = db.create_collection(
    name="ai_knowledge"
)

llm = OpenAI()
Initialization
Prepare the embedding model, vector database and LLM client. Configure OPENAI_API_KEY and OPENAI_MODEL in your environment before running.

Step 2 — Prepare the knowledge base

python
documents = [
    "Tokenization converts text into tokens.",
    "The model predicts probabilities for the next token.",
    "Decoding selects a token and repeats the process.",
    "Pizza is an Italian dish."
]

ids = ["doc1", "doc2", "doc3", "doc4"]

Step 3 — Embed and store the documents

python
vectors = embedding_model.encode(
    documents,
    normalize_embeddings=True
).tolist()

collection.add(
    ids=ids,
    documents=documents,
    embeddings=vectors
)

Step 4 — Retrieve relevant chunks

python
question = "How does an LLM generate text?"

query_vector = embedding_model.encode(
    [question],
    normalize_embeddings=True
).tolist()

results = collection.query(
    query_embeddings=query_vector,
    n_results=3
)

retrieved_documents = results["documents"][0]
retrieved_ids = results["ids"][0]

Step 5 — Construct the augmented prompt

python
context = "\n".join(
    f"[{doc_id}] {document}"
    for doc_id, document in zip(
        retrieved_ids,
        retrieved_documents
    )
)

prompt = f"""
Use the following context to answer the question.
Cite the supporting document IDs.
If the context is insufficient, say so.

Context:
{context}

Question:
{question}
"""

Step 6 — Generate the answer

python
response = llm.responses.create(
    model=os.environ["OPENAI_MODEL"],
    input=prompt

print(response.output_text)
