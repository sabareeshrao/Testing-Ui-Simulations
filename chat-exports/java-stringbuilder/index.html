Interview question: What is the StringBuilder class in Java, and why do we need it?

Imagine Java has a String class, but StringBuilder has not yet been invented. Our task is to build a large text document efficiently.

Phase 1 — Discovering the problem

IDEA 01 / 15

How can a programming language represent text?

Represent text as an ordered sequence of characters.

Starting idea: A sequence representing textual information.

IDEA 02 / 15

What if multiple variables share the same text object?

String a = class="str">"Java";
String b = a;

If changing a could modify the shared object, b might unexpectedly change too.

Introduce a rule: once a String is created, its textual content cannot change.

Invention: String immutability.

This makes shared text predictable, supports string pooling and simplifies concurrent reading.

IDEA 03 / 15

How do we change something that cannot change?

String text = class="str">"Java";
text = text + class="str">" 21";

We are not modifying the original String object. We are producing a new String value and assigning its reference to text.

Idea: Change the reference instead of changing immutable content.

IDEA 04 / 15

What happens when we concatenate inside a loop?

String result = class="str">"";

for (int i = 0; i < 5; i++) {
    result = result + class="str">"A";
}

Each iteration constructs a larger String value containing the previous content.

For five iterations, our straightforward implementation writes:

1 + 2 + 3 + 4 + 5 = 15

character units, even though the final result contains only five.

Problem: Repeatedly reconstructing an expanding immutable value creates unnecessary copying.

IDEA 05 / 15

Our program is generating temporary garbage

Old intermediate String objects may become unreachable when no reference to them remains.

As the loop grows, repeated allocation and copying can increase memory pressure and garbage collection work.

Final text length10,000

n(n+1) / 2 = O(n²)

New challenge: Can we build text without constantly creating replacement String objects?

Phase 2 — Inventing StringBuilder

IDEA 06 / 15

What if we allow text to be modified temporarily?

We don't need to make the original String class mutable. Instead, introduce another class specifically designed for constructing and editing text.

Use it while building the document, then produce an ordinary String once the work is finished.

Invention: A separate mutable character sequence.

IDEA 07 / 15

Reserve extra memory before we need it

Instead of allocating exactly enough storage for the current text, reserve additional space for future characters.

New text can be written into the unused region.

StringBuilder sb = new StringBuilder(12);

sb.append(class="str">"Java");
sb.append(class="str">" 21");
sb.append(class="str">"!");

Invention: A reusable internal buffer.

The cells represent logical UTF-16 code units, not the literal internal byte layout.

IDEA 08 / 15

Separate occupied space from available space

StringBuilder sb = new StringBuilder();
sb.append(class="str">"Java");

System.out.println(sb.length());
System.out.println(sb.capacity());

Invention: Length and capacity as separate properties.

Java's default empty StringBuilder has an initial capacity of 16.

IDEA 09 / 15

What if the reserved memory becomes full?

When more storage is required, allocate a larger buffer and transfer the existing content into it.

For ordinary capacity expansion, the documented growth rule is:

max(required, 2 × old capacity + 2)
StringBuilder sb = new StringBuilder(4);

sb.append(class="str">"Java");
sb.append(class="str">"21");

System.out.println(sb.capacity()); // 10

Invention: Automatically resizable storage.

Capacity growth is subject to implementation and maximum-size limits.

IDEA 10 / 15

Stop recreating the entire text after every addition

StringBuilder sb = new StringBuilder();

sb.append(class="str">"A");
sb.append(class="str">"B");
sb.append(class="str">"C");

Each operation modifies the same builder object. When capacity is sufficient, existing content does not need to be copied into a new buffer.

We have invented the core idea of StringBuilder.

Build text incrementally using mutable, expandable storage.

IDEA 11 / 15

IDEA 14 / 15

What happens when multiple threads modify the same buffer?

If two threads modify shared mutable state without coordination, they may overwrite each other's work or leave the buffer inconsistent.

Introduce synchronization when shared access is necessary.

IDEA 15 / 15

Why does Java provide three different classes for text?

String Immutable
String name = class="str">"Java";

Use it for ordinary text, identifiers, configuration values and completed results.

StringBuilder Mutable

Java interview answer

Interviewer: What is the StringBuilder class?

StringBuilder is a mutable character-sequence class in the java.lang package. Unlike String, it allows us to modify textual content without creating a new String for every modification.

It maintains an expandable internal buffer and provides methods such as append(), insert(), delete(), replace() and reverse().

It is particularly useful for repeated string concatenation inside loops. Unlike StringBuffer, it does not provide synchronization guarantees, making it generally preferable for single-threaded or thread-confined text construction.

We can convert its contents into an immutable String using toString().

Important Java 21 interview trap

Interviewer: Is StringBuilder always faster than the + operator?

No.

Simple concatenation
String result = firstName + class="str">" " + lastName;

Modern Java can optimize a single concatenation expression. Explicit StringBuilder usage is not automatically faster.

Repeated concatenation
StringBuilder sb = new StringBuilder();

for (int i = 0; i < 10_000; i++) {
    sb.append(i);
}

String result = sb.toString();

StringBuilder is usually a better choice when accumulating text across many loop iterations.

Java 8's compiler commonly translated dynamic concatenation expressions into StringBuilder operations. Java 17 and Java 21 can instead use invokedynamic with StringConcatFactory, allowing more flexible concatenation optimizations.

Modern OpenJDK implementations also use byte-based internal storage with Latin-1 or UTF-16 encoding rather than always using a char[]. Our diagrams represent logical character storage, not literal JVM object layouts.

Permanent engineering knowledge

Mutability

Allow controlled changes when repeatedly reconstructing an object is expensive.

Buffering

Reserve reusable storage for future operations.

Preallocation

Allocate sufficient capacity in advance to reduce resizing.

Geometric growth

Increase capacity progressively to reduce allocation frequency.

Amortization

Spread occasional expensive operations across many inexpensive ones.

Immutable publication

Construct information privately, then expose a stable result.

Concurrency control

Coordinate access when mutable resources are shared.
