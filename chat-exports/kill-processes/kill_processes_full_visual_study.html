Kill Processes in Linux

The kill command is a Linux process management command used to send signals to running processes.

Despite its name, kill does not always terminate a process. It can also pause, resume, interrupt or request a configuration reload, depending on the signal sent and how the process handles it.

1. Why do we need the kill command?

Unresponsive applications
An application freezes or stops responding.
High CPU usage
A process consumes excessive processing power.
Memory consumption
A problematic process consumes too much RAM.
Accidental execution
A command or background task was started unintentionally.
Background processes
An unnecessary background worker needs to stop.
System stability
Stop problematic applications safely.

3. Syntax of the kill command

kill
The command used to send a signal.
-TERM
Specifies the requested action.
2048
Identifies the target process.

General syntax:

bash
kill [signal or option] PID(s)

The default signal is SIGTERM when no signal is specified.

These three commands are equivalent:

bash
kill 2048

kill -15 2048

kill -SIGTERM 2048

4. What is a signal in Linux?

A signal is a notification delivered to a process to inform it of an event or request a particular action.

Depending on the signal, a process may handle it, ignore it or perform the operating system's default action. Some signals cannot be intercepted by the application.

Always prefer SIGTERM before escalating to SIGKILL. The kernel still reclaims process resources after forced termination, but the application cannot run its own cleanup procedures.

12. How kill works internally

The command does not directly remove a process from memory. It requests the operating system to deliver a signal.

A successful kill command generally indicates that the signal request succeeded. It does not guarantee that the target has already terminated.

13. Process permissions and sudo

Linux prevents unauthorized users from signaling processes owned by other users.

For example:

developer@linux:~$ kill -TERM 1024
bash: kill: (1024) - Operation not permitted
developer@linux:~$ sudo kill -TERM 1024
[sudo] password for developer:

Using sudo may grant sufficient privileges, provided the user is authorized and the operating environment permits it. Do not use elevated privileges unnecessarily.

16. Why does kill sometimes fail?

Invalid or nonexistent PID
No such process
The process may have already exited or the PID may be incorrect.
Verify the PID using ps or pgrep.
Insufficient permissions
Operation not permitted
The sender is not authorized to signal the target.
Check ownership and authorized privileges.
SIGTERM ignored
Process remains running
The application ignores or handles the termination request without exiting.
Investigate the process and escalate if necessary.
Uninterruptible sleep
Process remains in D state
The process is blocked inside an uninterruptible kernel operation.
Investigate storage, device or I/O problems.
Zombie process
Process remains in Z state
The process has already exited, but its parent has not collected its status.
Investigate the parent process.

Even SIGKILL may not make a process disappear immediately if it is stuck in uninterruptible kernel sleep. Sending SIGKILL to a zombie cannot remove it because the process has already exited.

19. Safe hands-on Linux practice

Instead of experimenting with important system processes, create a harmless temporary process using sleep.

Step 1 — Create a background process

bash
sleep 600 &

Step 2 — Store its PID

bash
PID=$!
echo "$PID"

Step 3 — Inspect the process

bash
ps -p "$PID" -o pid,stat,cmd

Step 4 — Suspend the process

bash
kill -STOP "$PID"

Step 5 — Resume the process

bash
kill -CONT "$PID"

Step 6 — Terminate the process

bash
kill -TERM "$PID"

Step 7 — Collect its exit status

bash
wait "$PID"
Practice the process lifecycle without interfering with an important application.
