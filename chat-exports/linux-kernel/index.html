How Linux Kernel Works — Detailed visual guide

01 · Linux kernel — The bridge between software and hardware

The Linux kernel is the privileged core of the operating system. It manages CPU time, memory, storage, networking and hardware devices. Applications request these resources through controlled interfaces rather than managing the hardware themselves.

02 · How Linux boots

systemd is a common init system, but alternatives exist.

When a computer starts, firmware hands control to a bootloader or another boot mechanism. The Linux kernel initializes the machine, establishes memory management, discovers devices and starts the first user-space process. That process brings the rest of the operating system to life.

03 · User mode vs. kernel mode

Applications execute with restricted privileges. Kernel code executes with elevated privileges, allowing it to configure memory mappings and control devices. A system call provides a controlled transition between these execution modes.

04 · What happens during a system call?

Illustrative x86-64 Linux syscall convention. *Assuming a successful full read.

When an application calls read(), the CPU enters the kernel using a special instruction. The kernel identifies the requested operation, checks the arguments, performs the work and returns the result. Other system calls create processes, allocate memory and communicate over networks.

05 · How Linux creates a process

Linux can create a child process using fork(). Parent and child initially share many physical memory pages through copy-on-write. The child can then use execve() to replace its program with a new executable while retaining its process ID.

06 · CPU scheduler — How thousands of tasks share CPU cores

The scheduler selects runnable tasks for each logical CPU. Modern Linux fair scheduling uses EEVDF principles to balance fairness and responsiveness. Tasks may be preempted, migrated between CPUs or put to sleep until a resource becomes available.

07 · Context switching — Inside a multitasking CPU

During a context switch, the kernel preserves the current task's execution state and restores another task's state. If necessary, it also changes the active memory address space. This enables applications to share a CPU without losing their progress.

08 · Virtual memory — Separate worlds inside the same RAM

Every process has its own virtual address space. Two processes can use identical virtual addresses while accessing different physical memory. Linux maintains the mappings and may deliberately share pages, such as read-only executable code, when appropriate.

09 · Page tables — How the CPU translates memory addresses

The CPU's Memory Management Unit (MMU) translates virtual addresses into physical addresses using page tables maintained by Linux. The TLB caches recent mappings, making repeated memory accesses much faster. This example assumes four-level paging and ordinary 4 KiB pages.

10 · Page faults and on-demand memory allocation

Linux can reserve virtual memory without immediately assigning physical memory to every page. When a valid but unmapped page is accessed, a page fault allows the kernel to establish the mapping. An invalid access, by contrast, can result in a segmentation fault.

11 · Virtual File System — How Linux understands different filesystems

The Virtual File System (VFS) gives applications a consistent way to access files regardless of the underlying filesystem. Linux resolves the pathname, associates it with filesystem objects and returns a file descriptor that the application can use for subsequent operations.

12 · How Linux reads data from an SSD

Linux first checks whether the requested file data is already cached in RAM. If it is not, the filesystem locates the storage blocks and submits an I/O request. The storage driver communicates with the SSD, and retrieved data can be cached for future reads.

13 · Hardware interrupts, device drivers and DMA

Device drivers translate kernel operations into hardware-specific commands. Direct Memory Access (DMA) allows supported devices to move data to or from RAM without the CPU copying every byte. Interrupts can notify the CPU when the device completes work or needs attention.

14 · Linux networking — Journey of an incoming packet

A network interface receives data and makes it available to the kernel. Linux commonly uses NAPI to efficiently process incoming packets. The networking stack interprets protocol headers, identifies the destination socket and delivers the resulting data to the application.

15 · Complete Linux kernel architecture

Simplified modern Linux architecture. x86-64 examples are used where applicable. Exact implementation details vary by kernel version, configuration and hardware.

Linux uses a modular monolithic kernel architecture. Its major subsystems operate within privileged kernel space and cooperate to manage system resources. Applications remain isolated in user space while the kernel coordinates execution, memory, storage, communication, security and physical hardware.
